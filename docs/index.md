# Halos Provider

The Halos provider manages **server-side state that is not policy-as-code** on a
[halo-server](https://github.com/dshakes/halos): service-account API tokens
(ADR-0036, scoped by ADR-0037), and read-only data sources for status.

## What it deliberately does not do

Halos policy is GitOps: it lives in a git policy repository and changes through
pull requests that a human merges. Halos' invariant is that **a human owns every
irreversible step**, so this provider has no resource for, and never wraps:

- policy files (manage the policy repository with the GitHub or GitLab provider and PR review),
- kill and unkill,
- approvals, promotions, rollout advances and rollbacks, merges,
- release publishing.

## Authentication

| Argument | Environment variable | Used for |
| --- | --- | --- |
| `endpoint` | `HALO_SERVER` | The halo-server base URL. https, unless the host is loopback. |
| `token` | `HALO_TOKEN` | A service-account token (`halo_sat_...`) for every call: data sources, refresh, import, destroy. |
| `session` | `HALO_SESSION` | An admin's `halo_session` cookie value. **Only needed to create** `halos_service_token`. |

halo-server only lets an interactive, signed-in admin create a service token
("a token cannot mint its successor", ADR-0036), so a service-account token
alone cannot apply a new `halos_service_token`. Typical setups:

- a human runs `apply` with `HALO_SESSION` set (sessions are short-lived), and automation
  later refreshes and destroys with the token;
- or automation only reads data sources with `HALO_TOKEN`.

Credentials are never written into error messages or logs, and redirects are
never followed. Prefer the environment variables so credentials stay out of
configuration.

## State contains secrets

`halos_service_token.token` is returned by halo-server once, at create, and has
to be kept in Terraform state. **Use an encrypted remote backend (or OpenTofu
state encryption) and restrict read access to state.** `sensitive` only hides the
value from CLI output.

## Example Usage

```terraform
terraform {
  required_providers {
    halos = {
      source = "dshakes/halos"
    }
  }
}

# endpoint, token and session may instead come from HALO_SERVER, HALO_TOKEN and
# HALO_SESSION, which keeps credentials out of configuration and state.
provider "halos" {
  endpoint = "https://halos.example.com"

  # Optional: trust a private CA, and bound each request.
  # ca_bundle_file = "/etc/ssl/acme-ca.pem"
  # timeout        = "30s"
}
```

### Optional

- `ca_bundle_file` (String) Path to a PEM file of CA certificates that replaces the system roots when verifying halo-server's certificate. May also be set with `HALO_CA_BUNDLE_FILE`.
- `endpoint` (String) halo-server base URL, for example `https://halos.example.com`. Must be https unless the host is loopback (`localhost`, `127.0.0.0/8`, `::1`). May also be set with the `HALO_SERVER` environment variable.
- `session` (String, Sensitive) Value of an admin's `halo_session` cookie. halo-server only lets an interactive session create service tokens (a token cannot mint its successor), so `halos_service_token` needs this; data sources, refresh and destroy work with `token` alone. May also be set with `HALO_SESSION`. Sessions are short-lived: prefer minting tokens from a human-run apply.
- `timeout` (String) Per-request timeout as a Go duration. Default `30s`, maximum `10m`.
- `token` (String, Sensitive) Service-account token (`halo_sat_...`, ADR-0036) used for every call. May also be set with `HALO_TOKEN`. A token cannot create service tokens; see `session`.
